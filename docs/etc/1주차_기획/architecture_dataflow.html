② 데이터 흐름 단계별 상세

처방전 업로드 → OCR → RAG → 결과 전송 → 챗봇 순서로 흐릅니다

STEP 1 — 업로드 (④ 박소정 · ③ 조성아)
보호자가 처방전 이미지 업로드 → React에서 multipart/form-data 전송
FastAPI: POST /api/v1/medical-records → S3 저장 → Redis XADD → "접수 완료" 즉시 응답
화면: "분석을 시작할게요" 처리중 애니메이션 표시 (어르신 큰 글씨)
↓
STEP 2 — OCR · 정보추출 (① 권순현)
OCR Worker: Redis XREAD → S3에서 이미지 로드 → CLOVA OCR API 호출
텍스트 파싱: 약품명 / 용량 / 복용법 / 복용횟수 / 진단명 추출
출력: REQ-002 JSON 스키마 변환 → DB(ExtractedMedication) 저장 → RAG XADD
실패 시: REQ-008 에러메시지 반환 → 재업로드 안내
↓
STEP 3 — RAG · 가이드생성 (② 김영혜)
RAG Worker: Redis XREAD → OCR 결과(JSON) 수신
① 벡터 검색: 약품명으로 FAISS 조회 → 식약처 데이터 top-3 추출
② 복약 가이드: 복용법·주의사항·병용금기 → gpt-4o-mini 프롬프트 생성
③ 생활습관 가이드: 진단명 기반 식이·운동 → gpt-4o-mini 생성
결과: DB(GuideResult) 저장 · source_refs(출처) 명시
↓
STEP 4 — 결과 전송 (③ 조성아)
RAG Worker: XACK 완료 → Redis Pub/Sub publish
FastAPI: Pub/Sub 구독 → 완료 수신 → SSE로 클라이언트에 결과 스트리밍
화면: 복약 가이드 + 생활습관 가이드 + 출처(식약처) 동시 표시
어르신용 큰 글씨 · "○○님이 대신 올려드렸어요" 투명 표시
↓
STEP 5 — 챗봇 질의응답 (③ 조성아)
어르신/보호자: "이 약 밥 먹고 먹어도 되나요?" 추가 질문
Chat Worker: POST /api/v1/chat → 대화이력(ChatHistory) 포함 → gpt-4o-mini 응답
SSE 스트리밍 응답 · 히스토리 저장(REQ-007)
하단 면책 고지 자동 표시 (REQ-011)
신뢰 설계
"의료진 대체 불가" 고지 항상 표시
출처(식약처) 명시 · 대리입력 투명 표시
예외 처리 (REQ-008)
OCR 실패 → 재업로드 안내
XCLAIM으로 장애 Worker 작업 재할당
