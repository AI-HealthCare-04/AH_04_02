## 1주차 (6/29~7/3) — 기획 + 인터페이스 합의

- 월: 킥오프, 요구사항/ERD/API명세서/와이어프레임 검토, 역할 배정 확정
- ①: 연동 테스트, 샘플 인식, 출력 스키마 1차 확정
- ②: 파이프라인 프로토타입, 의약품 데이터 소량 확보, 프롬프트 v1
- ③: FastAPI 골격, DB모델, 챗봇/업로드 엔드포인트 스켈레톤
- ④: 와이어프레임 확정, 프론트 셋업, Docker Compose 초안

**주간 완료기준**: API 계약(JSON 스키마) 문서화 완료 + 4명 각자 모듈 단독 실행 가능

## 2주차 (7/6~7/10) — 파이프라인 1차 연결

- 월: 1주차 회고, API계약 최종 확정
- ①: 인식률 개선(샘플 20장+), 에러케이스 처리(REQ-008)
- ②: 벡터DB 본격 구축(FAISS/Chroma), 프롬프트 v2, ① 결과 연동 테스트
- ③: ① 결과 DB저장 로직, 로그인/회원가입(REQ-006) 구현
- ④: 업로드·처리중화면 실제 구현 + 백엔드 API 연동 시작

**주간 완료기준**: 업로드 → OCR → DB저장까지 1차 end-to-end 연결

## 3주차 (7/13~7/17, 취업·기업특강 주간) — 핵심 파이프라인 완성

- 월: 특강 일정 고려해 작업시간 재배분
- ①: 정확도 측정·리포트 작성 (평가기준 3-1 대응)
- ②: 생활습관가이드 추가(REQ-004), 동일입력 결과편차 테스트 (평가기준 3-3)
- ③: 가이드결과 저장 API, 챗봇에 LLM 연동
- ④: 가이드결과화면·챗봇화면 구현

**주간 완료기준**: 업로드→가이드생성→화면표시 전체 흐름 1차 완성 (필수기능 3개 다 동작)

## 4주차 (7/20~7/24) — 고도화 + 내부 QA

- 월: 3주차 통합 이슈 리스트화
- ①: 여유되면 선택구현(이미지분류 기반 복약분석) 착수
- ②: 출처표시(source_refs) 정교화, 캐싱 적용 (REQ-009 응답속도)
- ③: 히스토리 API(REQ-007), 비동기 성능 점검 (평가기준 5-5)
- ④: 히스토리화면 구현, 전체 흐름 다듬기

**주간 완료기준**: 필수구현 3개 + 비기능요구사항(REQ-009~011) 전부 동작, 내부 QA 시작

## 5주차 (7/27~7/31) — 배포

- ①②③: 버그수정, 성능튜닝, 인증/인가 마무리 (평가기준 5-4)

**주간 완료기준**: 실제 서비스 URL 접속 가능 (데모데이 1주 전 배포 필수 — 평가기준 명시사항)
