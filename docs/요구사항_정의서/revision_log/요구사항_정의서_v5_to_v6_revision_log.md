# 요구사항 정의서 수정 검토 기록 (v5 → v6)

이 문서는 `요구사항_정의서_v5.xlsx`에서 `요구사항_정의서_v6.xlsx`로 변경하며 반영한 "처음 보는 사람도 이해할 수 있는 문서화" 개선 내역을 기록한 변경 이력이다.

## 배경 및 목적

- v5는 우선순위 재조정(아이젠하워 매트릭스)까지 반영했으나, 처음 문서를 접하는 사람이 용어·역할·전체 흐름을 파악하기 어렵다는 문제 제기가 있었다.
- 이번 개정의 목표는 **요구사항 내용을 바꾸지 않고**, 첫 독자가 문서만으로 전체 맥락을 이해할 수 있도록 설명·구조를 보강하는 것이다. 새 요구사항을 만들거나 기존 동작을 변경하지 않았다.
- 아울러 다른 작업 세션에서 진행 중인 ERD·API 명세서의 "신뢰관계 → 돌봄관계" 명칭 통일과 요구사항 정의서의 용어를 일치시켰다.

## 변경 항목

### 1. 비고 / 우선순위 재평가 근거 분리

- v5에서는 `비고`(H열)에 실제 구현·업무 메모와 `[아이젠하워 매트릭스 v5 재평가] High→Medium: <근거>` 형식의 우선순위 재평가 산문이 뒤섞여 있었다.
- 이를 분리해 **새 컬럼 `우선순위_재평가_근거`(J열)**를 신설하고, 모든 `[아이젠하워 매트릭스 …]` 텍스트를 그대로 이 컬럼으로 이동했다.
- `비고` 컬럼에는 순수한 구현·업무 메모만 남겼다(예: REQ-002는 "미가입 수신자는 전화번호 인증 가입·로그인 후 수락"만 유지). 재평가 산문이 없던 행의 비고는 그대로 두었다.
- 근거: 재평가 사유는 우선순위 히스토리 성격이므로, 상시 참조하는 구현 메모와 컬럼을 분리해야 첫 독자가 비고를 오해 없이 읽을 수 있다.

### 2. 신뢰관계 → 돌봄관계 용어 통일

- ERD(`trust_invitations → care_relation_invitations`, `trust_relations → care_relations`, `trustee_id → related_user_id`)와 API 명세("신뢰관계" 섹션 → "돌봄관계")의 명칭 변경에 맞춰, 본 문서의 `신뢰관계`·`신뢰관리` 표현을 `돌봄관계`·`돌봄관리`로 통일했다.
  - 카테고리: REQ-002~004의 `신뢰관리` → `돌봄관리`
  - 상세내용: REQ-003 "승인된 신뢰관계를 생성" → "돌봄관계", REQ-030 "…상태·신뢰관계·복약기록…" → "돌봄관계"
  - 비고: REQ-031 "리소스 소유권과 신뢰관계 검사" → "돌봄관계"
- **`care_level`(independent/guardian_check/third_party_needed)은 신뢰관계와 무관한 별개 개념이므로 변경하지 않았다.**
- `신뢰성`(REQ-032 카테고리, reliability)도 "신뢰관계"와 다른 비기능 품질 용어이므로 그대로 유지했다.
- 근거: 3개 산출물(요구사항·ERD·API)의 용어를 일치시켜 협업 시 혼선을 제거한다.

### 3. 용어집·핵심 흐름 시트 추가

- **`용어집` 시트(용어, 설명)** 신설: 첫 독자가 모르는 사용자·역할·상태 값을 한 곳에서 확인하도록 정의했다. `프로젝트의 목적` 시트와 REQ 행의 기존 서술을 근거로 하며 새 사실을 창작하지 않았다.
  - 복약관리 대상자, 보호자, 요양보호사, 생활지원사, 사회복지사, 지원인력(집합 용어), 교육자(로그인 역할이 아닌 업무 역할), `care_level` 3단계, 돌봄관계, 교육 단계 freshman/junior/senior를 각각 한 줄 설명으로 정의했다.
- **`핵심 흐름` 시트(흐름명, 단계)** 신설: 요구사항이 서로 어떻게 이어지는지 4개 end-to-end 시나리오로 정리했다. 각 단계에 근거 REQ-ID를 병기했다.
  - (a) 회원가입 → 보호자 초대 → 수락 (REQ-001~003)
  - (b) 상태 입력 → 자가복약 평가 → 알림 대상 결정 (REQ-005~007, 026c)
  - (c) 처방전 업로드 → OCR → 가이드 생성 → 챗봇 질문 (REQ-008~012, 021)
  - (d) 교육 시작 → 단계 전환 → 전화지원 기록 (REQ-040~044)
- 근거: 개별 요구사항만으로는 전체 그림이 보이지 않으므로, 흐름·용어를 별도 시트로 제공해 문서 진입 장벽을 낮춘다.

### 4. 인수조건 컬럼 추가

- `요구사항정의서` 시트에 **`인수조건` 컬럼(F열, 상세내용 바로 뒤)**을 신설하고 47개 REQ 전 행에 1~3개의 구체적 합격/불합격 기준을 작성했다.
- 모든 기준은 해당 행의 기존 `상세내용`·`비고`에서 직접 도출했으며 새 요구사항을 추가하지 않았다. 산문을 검증 가능한 형태로 바꾸는 것이 목적이다(예: REQ-004 "승인→revoked, 반려→approved 복귀", REQ-011 "0.80 미만 review_required 분류").
- 근거: "적절히 처리되어야 함" 같은 모호한 표현 대신, 통과 여부를 판정할 수 있는 기준을 명시해 QA·리뷰 기준을 공유한다.

## 시트/컬럼 구조 변경 요약

| 항목 | v5 | v6 |
|---|---|---|
| 시트 수 | 2 (요구사항정의서, 프로젝트의 목적) | 4 (+ 용어집, 핵심 흐름) |
| 요구사항정의서 컬럼 | 8 (A~H) | 10 (A~J, + 인수조건, 우선순위_재평가_근거) |
| 요구사항 행 수 | 47 | 47 (변동 없음) |

- v6 요구사항정의서 컬럼 순서: `ID, 구분, 카테고리, 요구사항명칭, 상세내용, 인수조건, 생활습관 개선 가이드/예시, 우선순위, 비고, 우선순위_재평가_근거`
- 서식: 전 시트 헤더 행 굵게·음영·고정(freeze A2), 장문 셀 wrap_text 적용, 컬럼 폭 조정.

## 팀에 설명할 핵심 결정

1. 이번 개정은 **요구사항 자체를 바꾸지 않는 "가독성·설명 보강" 작업**이다. 우선순위·상세내용·범위는 v5와 동일하며, 첫 독자가 이해하기 쉽도록 용어집·핵심 흐름·인수조건을 더하고 컬럼을 정리했을 뿐이다.
2. `비고`에 섞여 있던 아이젠하워 재평가 근거는 별도 컬럼(`우선순위_재평가_근거`)으로 분리했다. 재평가 히스토리와 상시 구현 메모의 성격이 달라 혼동을 유발했기 때문이다.
3. `신뢰관계 → 돌봄관계` 명칭 통일은 ERD·API 명세 변경과 세트로 진행한 것이며, **별개 개념인 `care_level`과 품질 용어 `신뢰성`은 의도적으로 그대로 두었다.**
4. `인수조건`은 기존 상세내용·비고에서만 도출했고 새 조건을 만들지 않았다. QA·리뷰가 동일 기준으로 합격 여부를 판정하도록 하는 것이 목적이다.
5. `요구사항_정의서_v5.xlsx`는 수정하지 않고 보존했으며, 본 개정은 `요구사항_정의서_v6.xlsx`로 버전업했다.
