# 요구사항 정의서 수정 검토 기록 — v10 → v11

> 버전: v10 → v11 · 날짜: 2026-07-28 · 작성자: 김영혜

## 변경 배경

API명세서_v11·ERD_v11과 동일한 근거(v10 이후 dev 90개 커밋)로 갱신했다.

## 주요 변경

- **REQ-005~007(자가진단)**: "보류"에서 **"구현취소"**로 재정정 — 2026-07-17 회의에서 목적 폐기가 결정된 이후, 2026-07-28 재조사로 관련 API·테이블이 코드에서 실제로 삭제된 것을 확인했다. 보호자/지원인력 시트의 REQ-006도 동일하게 정정.
- **REQ-004(돌봄관계 해제)**: 상세내용·근거를 "care_level 기반"에서 "organization 여부 기반"으로 갱신, 신설 REQ-066을 참조하도록 정리.
- **REQ-026a/026c**: Web Push 백엔드 추가 및 자가진단 구현취소의 연쇄 영향을 반영해 근거 갱신(상태 자체는 "부분" 유지).
- **신규 REQ-063~075(13개)**: 보호자·기관 처방전 검토(063), 처방전 사진 저장·열람(064), 계정전환/세션 보안 재설계(065), 기관 연결해제 사유·승인(066), 알림함(067), Web Push(068, 백엔드만), 다중환자 모니터링(069), 환자관리 표 UI(070), 내 정보 자가수정(071), 가입 실시간 중복확인(072), 일정별 알림대상 지정(073), 등록내역 즐겨찾기(074), 최소 감사로그(075). 전부 공통 시트에 추가하고, 비대칭이 뚜렷한 일부(063/064/066)는 복약관리대상자·보호자·지원인력 시트에도 역할별 상세 행을 추가했다.
- **`v11 변경요약` 시트**: 기존 `v10 변경요약` 시트를 대체(과거 버전 요약은 누적하지 않고 최신 버전만 유지하는 기존 관례를 따름 — 과거 이력은 git 이력과 revision_logs로 추적).
- **용어집**: "자가진단(폐기)" 항목을 "자가진단(구현취소)"로 갱신, `care_level` 설명에 코드 삭제 사실 추가, 보호자·기관 검토/돌봄관계 해제 재설계/알림함/Web Push 4개 용어 신규 추가.
- **핵심 흐름 시트**: "처방전 확정 → 보호자·기관 검토" 흐름(공통), "기관 계정의 연결해제 → 사유 입력 → 승인/자동확정" 흐름(보호자) 2건 신규 추가.

## 이번 버전의 한계 (다음 버전에서 보강 필요)

- v9→v10은 여러 라운드의 코드 재조사("3라운드 정합성 감사" 등)를 거쳤으나, 이번 v11은 백그라운드 조사 1건(90개 커밋 diff 전수 조사 + 직접 코드 확인 일부)만으로 작성했다. REQ-063~075는 전부 이번에 처음 번호가 매겨진 신규 항목이라, 다음 버전에서 재검증(특히 인수조건 문구가 실제 코드 동작과 정확히 일치하는지)이 필요하다.
- 역할별 상세 행(복약관리대상자/보호자/지원인력 시트)은 REQ-059~062 때처럼 신규 REQ 전체를 다 상세화하지 못했고, 비대칭이 뚜렷한 063/064/066만 추가했다. REQ-067~081도 역할별 뉘앙스가 있다면 후속 버전에서 상세화할 것.
- 감사로그는 신규 REQ 중 유일하게 063~074 순번을 따르지 않고 **REQ-081**을 쓴다 — `backend/models.py`·`backend/core/audit.py`의 코드 주석이 이미 이 기능을 REQ-081로 표기하고 있어서, 순번상 REQ-075가 될 자리였지만 코드 쪽 번호를 그대로 채택했다(REQ-037/058 때 겪었던 코드-문서 번호 불일치 재발 방지).
