# 요구사항 정의서 수정 검토 기록 — v11 → v12

> 버전: v11 → v12 · 날짜: 2026-08-03 · 작성자: 김영혜(Claude 세션)

## 변경 배경

API명세서_v12·ERD_v12와 동일한 근거(v11 이후 dev 100개 커밋)로, REQ-001~081 전체(공통/복약관리대상자/보호자/지원인력 4개 시트)를 실제 코드와 대조해 재검증했다.

## 주요 변경

- **상태 업그레이드 5건** (스프레드시트 작성 이후 실제로 완료 확인):
  - REQ-021(챗봇 SSE): 부분 → 완료
  - REQ-026a/REQ-068(Web Push): 부분 → 완료 — 프론트 구독 흐름 추가 확인(커밋 `1418661`)
  - REQ-056(보호자 전용 상단메뉴): 미구현 → 완료 — 이 기능은 v11 스프레드시트 기준일(2026-07-28)보다 4일 앞선 커밋(`b419862`, 2026-07-24)이라, 스프레드시트가 작성 시점부터 이미 틀렸던 것으로 확인됨
  - REQ-057(알림→확인화면 연결): 부분 → 완료
  - REQ-051(식사시간 활용): 부분(수집만) → 완료
- **재분류 1건**: REQ-049(자동로그인/기본화면) "확인필요" → "미구현(확정)" — App.tsx/Landing.tsx에 해당 계약 자체가 없음을 코드로 확인.
- **모순 플래그(상태 미변경, 팀 확인 필요)**: REQ-048(챗봇 진입버튼 항상노출) — 문서는 "조건부 게이팅 제거, 항상 노출"이라 하지만 실제 코드(`PrescriptionReview.tsx:955-981`)는 정반대로 게이팅하고 있음. v12는 상태를 바꾸지 않고 눈에 띄게 각주만 추가했다.
- **서술 오류 정정 4건** (상태는 "완료" 유지, 세부 서술만 수정): REQ-019(질환 목록·규칙 개수), REQ-059(403이 아니라 404), REQ-014(url 필드·타임스탬프 없음), REQ-008(10MB 제한이 프론트 전용).
- **신규 REQ-082 추가**: 환자별/보호자별 push 알림 음소거(커밋 `24dbb8f`, `caregiver_patients.notifications_enabled`) — 공통 시트 + 보호자 시트에 상세 행 추가. REQ-026c(사용자 전역 토글)·REQ-067(알림함)과는 별개 개념.
- **`v11 변경요약` 시트**를 `v12 변경요약`으로 대체(기존 관례대로 과거 버전 요약은 누적하지 않음).
- **용어집**에 4개 용어 신규 추가: `notifications_enabled`, 저장된 계정 전환/자동 로그인 해제, `AUTO_GUIDE_MATCH_THRESHOLD`, 자동가이드 대상 적격.

## 검증 방법

REQ-001~081 전체를 라우터(`care_router.py`/`monitoring_router.py`/`chat_router.py`/`auth_router.py` 등)·프론트(`NavBar.tsx`/`sw.ts`/`push.ts`/`records_router.py`_resolve_time_slot 등)의 실제 코드와 1건씩 file:line 단위로 대조. 대부분(REQ-001~007a, 009~013, 015~018, 020, 022~024, 026b, 031, 035~039, 040~044, 047, 050, 052~053, 058, 060~067, 069~074, 081)은 v11 상태가 그대로 정확함을 확인했다.

## 이번 버전의 한계 (다음 버전에서 보강 필요)

- 이번 v12는 요구사항 감사 1건(전체 REQ 코드 대조)을 근거로 작성했다. 원래 3라운드(비평 2인+수정 1인×3) 서브에이전트 토의를 계획했으나, 세션 한도·에이전트 응답 정체(stall) 문제로 초안 생성 자체가 손상되는 사고가 있었다(자세한 내용 아래 참고) — 결국 이 리비전은 감사 결과를 기반으로 직접 편집했고, 별도의 다인 비평 라운드는 거치지 못했다. 다음 버전에서 재검증을 권장한다.
- **REQ-026d(공동알림·완료공유)**: 전제(third_party_needed 자자진단 연동)가 코드에서 이미 삭제된 것으로 확인됐다 — "미구현"으로 계속 추적하는 것이 오히려 오해 소지가 있어 폐지를 권고하나, 이번 버전에서는 팀 논의 없이 임의로 폐지하지 않고 상태를 유지했다.
- Langfuse 트레이싱/자동채점, 실행형(actionable) push 액션버튼은 사용자향 요구사항이 아닌 내부/운영 기능으로 판단해 이번엔 REQ 번호를 부여하지 않았다 — 필요시 별도 운영 문서로 관리할 것을 권고한다.
- REQ-048의 모순은 팀 확인이 필요한 상태로 남아있다 — 다음 버전 전에 반드시 해소할 것.

## 부록: 이번 버전 작성 중 발생한 사고 기록

v12를 서브에이전트 3라운드 토의(초안→비평 2인→수정 1인, 3회 반복)로 작성하려 했으나, 요구사항_정의서 초안을 생성하는 에이전트 호출에서 출력이 물리적으로 잘리는 사고가 있었다(문서 앞부분 "진료기록입력"이 "료기록입력"으로 시작 — SHEET: 공통/복약관리대상자 전체와 SHEET: 보호자 앞부분이 누락됨). 이후 비평·수정 라운드가 이 손상된 초안을 계속 이어받아, 여러 리뷰어가 "검증 불가"만 반복 보고했다. 세션 한도·에이전트 응답 정체 문제까지 겹쳐 서브에이전트 파이프라인으로는 완결하지 못했고, 결국 v11 원본을 직접(openpyxl로) 편집하는 방식으로 전환해 이 v12를 완성했다. API명세서_v12·ERD_v12는 같은 파이프라인에서 초안→1라운드 비평/수정까지는 정상적으로 완주했다.
