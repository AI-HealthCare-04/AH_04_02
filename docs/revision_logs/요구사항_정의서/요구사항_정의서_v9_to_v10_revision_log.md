# 요구사항 정의서 수정 검토 기록 — v9 → v10

> 버전: v9 → v10 · 날짜: 2026-07-22 · 작성자: 김영혜

## 변경 배경

API명세서_v10·ERD_v10과 맞춰, PR #69 이후 실제 동작이 생긴 연결관리/내약관리/삭제 동기화 요구사항을 문서화했다. v9 기존 시트는 보존하고, v10 파일에는 신규 요구사항 행과 `v10 변경요약` 시트를 추가했다.

## 신규/보강 요구사항

| REQ | 내용 | 상태 |
|---|---|---|
| REQ-059 | 대기중 초대 삭제/취소 | 완료 |
| REQ-060 | 보호자/지원인력 받은 초대함에서 수락·거절 | 완료 |
| REQ-061 | 환자 내약 등록/조회/수정/삭제 | 완료 |
| REQ-062 | 처방전 삭제 시 연결 내약·일정 동기화 | 완료 |
| REQ-040~044 | 지원인력 교육지원/교육·추적관리 | 구현취소 |

## 정정 사항

- REQ-001의 refresh token 재발급 endpoint를 실제 코드 기준 `POST /auth/token/refresh`로 맞췄다.
- 문서 관점에서 RESTful 의미가 드러나도록 `patients/{patient_id}` 하위 리소스와 `invitations` 상태 전환을 설명했다.
- 지원인력 교육지원/교육·추적관리(REQ-040~044)는 더 이상 다음 스프린트 후보로 두지 않고 제품 범위에서 제외하기로 하여, 요구사항정의서 상태를 `미구현`에서 `구현취소`로 정정했다.

## 보호자·지원인력 시트 상세화 추가 반영

- 공통 시트에만 있던 REQ-059~062를 보호자 시트와 지원인력 시트에도 각각 추가했다.
- 같은 REQ 번호를 재사용하되 User Story, 상세내용, 인수조건, 구현 판단 근거를 각 클라이언트 그룹의 실제 사용 맥락으로 다시 작성했다.
- 보호자는 가족/보호자 관점의 환자 초대 취소, 받은 초대함, 담당 환자 내약 관리, 처방전 삭제 동기화를 중심으로 정리했다.
- 지원인력은 현장 업무 관점의 담당 환자 연결, 방문 중 내약 등록, 잘못 등록된 처방전 정리, 업무 배정 변경 시 초대 취소를 중심으로 정리했다.

## 핵심 흐름 시트 클라이언트 그룹별 상세화

- 기존 핵심 흐름 시트는 5개 흐름을 공통 서술로만 적어 환자·보호자·지원인력의 실제 사용 차이가 잘 드러나지 않았다.
- v10에서는 컬럼을 "클라이언트 그룹 / 흐름명 / 상세 단계 / 관련 REQ / 구현 상태 / 검토·후속 작업"으로 재구성했다.
- 복약관리대상자, 보호자, 지원인력, 공통 흐름을 분리해 회원가입·초대·처방전 OCR·내약 등록·복약기록·챗봇·식사시간 입력 흐름을 각각 상세 기재하고, 교육관리 흐름은 구현취소로 별도 표시했다.
- 구현 상태는 완료/부분/미구현/보류를 그대로 유지하되, 왜 그런 상태인지 후속 작업 칸에서 바로 볼 수 있게 했다.
