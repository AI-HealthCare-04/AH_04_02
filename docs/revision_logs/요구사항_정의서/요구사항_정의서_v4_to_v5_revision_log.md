# 요구사항 정의서 수정 검토 기록 (v4 → v5)

이 문서는 `요구사항_정의서_v4.xlsx`에서 `요구사항_정의서_v5.xlsx`로 변경하며 반영한 우선순위 재조정 내역을 기록한 변경 이력이다.

## 배경 및 목적

- v4 기준 우선순위 High 항목은 총 37개(전체 47개 요구사항 중)로, 릴리스 초기 범위가 과밀하다는 문제 제기가 있었다.
- High의 약 50%를 Medium으로 재조정하여 초기 릴리스 범위를 현실화하기로 결정했다.
- 재조정 기준은 **아이젠하워 매트릭스**(긴급도=기존 우선순위, 중요도=severity/영향도)를 적용했다. 원문서에는 severity 컬럼이 없어, 환자 안전 직접 영향·법적/보안 필수 여부를 기준으로 항목별 severity(High/Medium/Low)를 새로 판정한 뒤 매트릭스에 배치했다.
  - Q1(우선순위 High + Severity High) → **High 유지** ("즉시 실행")
  - Q2(우선순위 High + Severity Medium/Low) → **Medium 강등 후보** ("일정 조정")

## 재평가 범위와 한계 (2026-07-02 점검 결과 추가)

`요구사항_정의서_v5.xlsx`와 본 로그를 재검증한 결과, 강등된 19건과 유지된 18건의 REQ-ID·통계는 서로 정확히 일치함을 확인했다. 다만 "priority × severity 아이젠하워 매트릭스 기반 재평가"라는 표현이 실제로 수행한 범위보다 넓게 읽힐 수 있어, 아래 한계를 명확히 남긴다.

- **단방향 검토였다.** 이번 작업은 기존 우선순위 High 37건을 대상으로 Q1(유지)/Q2(강등 후보) 두 분면만 적용한 검토였다. 아이젠하워 매트릭스의 나머지 두 분면, 즉 Q3(원래 Medium/Low priority + High severity → 승격 후보)와 Q4(Medium/Low priority + Low severity)는 검토 대상에 포함하지 않았다. 원래 Medium/Low였던 10건(REQ-007a, REQ-013, REQ-018, REQ-019, REQ-020, REQ-022, REQ-027, REQ-028, REQ-029, REQ-034)은 severity 기준으로 재평가되지 않고 v4 값을 그대로 유지했다.
- **Severity는 구조화된 값이 아니다.** 문서(xlsx)에는 별도의 Severity 컬럼이 없다. 강등된 19건에 한해 H열(비고)에 `[아이젠하워 매트릭스 v5 재평가] High→Medium: <근거>` 형식의 산문으로 판정 근거를 남겼을 뿐, High로 유지된 18건과 원래 Medium/Low였던 10건에는 severity 판정이 별도로 기록되어 있지 않다.
- **결론.** 수치(37→18/27/2, 강등 51.4%)와 강등·유지 목록 자체는 정확하며 목표("약 50% 감축")도 충족했다. 그러나 이는 엄밀한 4분면 전수 재평가가 아니라 "기존 High 항목 내부의 단방향 강등 검토"였다는 점을 팀에 투명하게 공유한다. 전체 47건에 대한 구조화된 Severity 컬럼 추가 및 Q3/Q4 포함 완전한 매트릭스 재평가가 필요하면 별도 작업(v6)으로 진행한다.

## 팀에 설명할 핵심 결정

1. 우선순위 재조정은 삭제나 범위 축소가 아니라 "실행 순서" 조정이며, Medium으로 내려간 항목도 요구사항 자체는 그대로 유효하다.
2. 재조정 기준은 아이젠하워 매트릭스(긴급도=우선순위, 중요도=환자안전·보안·법적 영향도)이며, 안전·보안·법적 컴플라이언스 관련 항목(인증, 암호화, 의료자문 고지, 탈퇴, 계정 잠금 등)은 전부 High를 유지했다. 단, 이번 재평가는 기존 High 37건 내부의 단방향 강등 검토였고 Severity는 구조화된 컬럼이 아닌 비고란 산문으로만 기록되었다(자세한 범위·한계는 "재평가 범위와 한계" 절 참고).
3. 알림(REQ-026 계열)은 발송(026a)·수신설정(026c)·일정관리(026b)·공동알림(026d) 4개가 서로 종속적인 게이트키퍼 관계이므로 세트 전체를 High로 유지해 논리적 일관성을 지켰다.
4. REQ-004(연결 해제)는 저빈도·고파급력 리스크가 있으나 설계상 승인 절차가 이미 안전장치로 내장되어 있어 Medium으로 조정하되, 보안 기능과 동시 배포를 권고사항으로 첨부했다.
5. 이번 검토는 원래 계획된 GPT-5(Codex) 외부 연동 대신 Claude 서브에이전트가 독립 검토자 역할을 맡아 5라운드 반박·조정을 거쳐 도출한 결과이며, 필요 시 실제 Codex 연동 환경에서 재검증할 것을 권장한다.
