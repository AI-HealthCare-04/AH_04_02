## 1. 전체 현황

`요구사항_정의서_v10.xlsx`의 클라이언트 그룹별 요구사항 행은 총 96개입니다.

| 상태 | 건수 | 비고 |
|---|---:|---|
| 완료 | 68 | 기능 구현 근거가 있는 항목 |
| 부분 | 13 | 구현은 있으나 테스트/UX/운영 검증이 남은 항목 |
| 미구현 | 5 | 아직 코드 또는 화면 근거가 부족한 항목 |
| 보류 | 4 | 회의 결정으로 현재 범위에서 중단한 항목 |
| 구현취소 | 5 | 지원인력 교육지원 등 제품 범위에서 제외된 항목 |
| 확인필요 | 1 | 브라우저 실측이 필요한 항목 |

같은 REQ가 보호자/지원인력 시트에 반복되는 구조라, 위 숫자는 기능 개수가 아니라 클라이언트 그룹별 검토 행 기준입니다.

## 2. dev 기준으로 문서와 달랐던 주요 항목

### REQ-026a / REQ-026c 알림

v10에는 실제 발송 채널이 이메일 중심으로 설명되어 있었지만, 최신 dev에는 Web Push 구독 UI와 서비스워커가 추가되었습니다.

- 확인 코드: `frontend/src/api/push.ts`
- 확인 코드: `frontend/src/sw.ts`
- 확인 코드: `frontend/src/pages/Notification.tsx`
- 확인 코드: `backend/core/scheduler.py`

다만 실제 팀 로컬/배포 환경에서 알림 수신 테스트가 완료된 것은 아니므로 `완료`가 아니라 `부분`을 유지합니다.

### REQ-056 보호자/지원인력 상단 메뉴

v10에는 보호자 전용 상단 메뉴가 미구현으로 되어 있었지만, 최신 dev의 `NavBar.tsx`는 `getCurrentCaregiverId()` 기준으로 환자 메뉴와 보호자/지원인력 메뉴를 분기합니다.

- 보호자/지원인력 상단 메뉴: `환자 관리`, `모니터링`, `알림함`, `연결관리`, `설정`
- 변경 판단: `미구현` → `완료`

단, 회의에서 말한 전체 메뉴 삭제와 메뉴명 정리는 `REQ-055`의 후속 작업으로 남아 있습니다.

### REQ-055 메뉴 구조

모바일 햄버거 메뉴와 역할별 메뉴 분기는 구현되어 있지만, 데스크톱 `전체 메뉴` 드롭다운은 아직 남아 있습니다.

또한 회의에서 정한 최종 메뉴명과 재배치가 완전히 반영되지 않았습니다.

- `처방전 등록` 또는 `처방 약 등록` → `처방등록`
- `오늘의 복약` → `복약기록` 흐름으로 통합
- `복약일정` → `알림내역` 또는 알림/일정 통합 명칭으로 정리

따라서 `REQ-055`는 `부분` 유지가 적절합니다.

### REQ-049 로그인 상태 진입

로그인 상태 표시와 NavBar 호출부 오류는 개선되어 있지만, 앱을 다시 열었을 때 refresh token으로 자동 로그인 후 역할별 홈으로 보내는 흐름은 브라우저 실측이 필요합니다.

따라서 `REQ-049`는 `확인필요` 유지가 적절합니다.

### 보호자/지원인력 수정요청 흐름

최신 dev에는 보호자/지원인력이 처방전 필드별로 수정 요청을 남기고, 환자가 해당 요청을 확인하는 흐름이 들어와 있습니다.

- 확인 코드: `frontend/src/pages/MedGuide.tsx`
- 확인 코드: `frontend/src/pages/PrescriptionReview.tsx`
- 확인 코드: `backend/routers/records_router.py`

이 내용은 요구사항정의서 v11에서 핵심 흐름과 구현 근거에 반영했습니다.

## 3. v11에 반영한 결론

1. `REQ-026a`: Web Push 구조 추가를 근거에 반영하되 실제 수신 테스트 전이므로 `부분` 유지
2. `REQ-026c`: 기기별 Web Push 구독/해지 UI 반영, 실제 수신 검증 전이므로 `부분` 유지
3. `REQ-049`: 자동 홈 진입은 실측 필요하므로 `확인필요` 유지
4. `REQ-055`: 역할별 메뉴 진전은 반영하되 전체 메뉴/명칭 정리 미완료로 `부분` 유지
5. `REQ-056`: 보호자/지원인력 상단 메뉴 분기 확인으로 `완료` 정정
6. 핵심 흐름: 알림, 연결관리, 챗봇/RAG/DUR, 보호자 수정요청 흐름의 최신 dev 상태 반영
7. API명세서: `/push/vapid-public-key`, `/push-subscriptions` 등록/삭제 API 반영
8. ERD: `push_subscriptions` 테이블과 알림 요구사항 추적 상태 반영

## 4. 팀 후속 확인 필요

1. Web Push 알림을 실제 기기/브라우저에서 수신하는지 확인
2. 알림 클릭 후 복약 확인 화면으로 자연스럽게 이동하는지 확인
3. `전체 메뉴` 삭제 여부와 최종 메뉴명 확정
4. 앱 재접속 시 로그인 상태에 따른 첫 화면 이동 규칙 확인
5. 요구사항정의서 v11, API명세서, ERD 간 REQ 번호와 상태가 다시 어긋나지 않는지 확인
